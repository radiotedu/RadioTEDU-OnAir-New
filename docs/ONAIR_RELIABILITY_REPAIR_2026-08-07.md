# RadioTEDU OnAir reliability repair — 2026-08-07

## Outcome

Make the installed OnAir console report only verified broadcast output, recover cleanly after a backend/audio crash, and coexist with the legacy Broadcast Wall without authentication races or misleading stale playback.

## Evidence and root cause

- The legacy Wall and OnAir shell both use `127.0.0.1:8100` and `C:\ProgramData\RadioTEDU\OnAir\cleanroom.db`; the shell window does not own the broadcast.
- At investigation time, port 8100 was listening but no FFmpeg source or Icecast connection existed. Both the origin and public `/lofi` mounts returned HTTP 404, and `/api/public/stations` reported every station offline.
- The database still contained `playing` rows from hours earlier. The operator timeline rendered those rows without requiring a live runtime, so a stopped station looked active.
- The continuity guard launches Uvicorn and the packaged backend with `--lifespan off`. That skips startup reconciliation, station autostart, library watchers, product catalogs, managed-service startup, checkpoints, and other recovery hooks.
- The legacy Wall and new OnAir shell can share the same WebView2 profile. Concurrent 401 responses also trigger parallel refresh requests inside one shell. With rotating refresh tokens, either case can invalidate the token another request is using.
- Track metadata can contain downloader sentinel values such as `stream_error`, which the UI displayed as an artist name.

## Repair design

1. Launch guarded backends with lifespan enabled and explicitly skip optional AI preload, keeping deterministic broadcast recovery and background maintenance active.
2. Change startup reconciliation from “fail interrupted item” to “requeue interrupted item at its existing position,” reset playout ownership transactionally, and test crash recovery.
3. Treat the public station summary as the authoritative end-to-end broadcast signal. A station is live only when the scheduler, program process, required outputs, and Icecast origin agree.
4. Never expose a stale database `playing` row as `now_playing` while the station is offline or degraded. Expose it as a preserved item for restart instead.
5. Stop the operator timeline clock while output is not verified. Show the preserved item and an explicit restart-from-beginning message.
6. Require end-to-end public status during Start verification; do not show a success banner for process-only health.
7. Use a single in-flight refresh request per shell, retain rotating refresh tokens, and isolate the OnAir WebView2 profile from the legacy Wall profile.
8. Sanitize known metadata sentinel values so `stream_error` is not presented as an artist.

## Safety boundaries

- Preserve the existing uncommitted metadata, library-watcher, and station-worker work.
- Do not delete the large untracked archive artifact or unrelated files.
- Do not silently enable per-station broadcast autostart; the operator’s restart-policy choice remains authoritative.
- Do not claim success from UI state alone. Verify process state, API state, and the actual Icecast mount.

## Acceptance criteria

- An offline station with an orphaned database row is shown as stopped, with the item preserved for restart and no countdown.
- Backend restart requeues interrupted manual, ad, and scheduled items without advancing queue order.
- Start is confirmed only after `/api/public/stations` reports the selected station `live`.
- The `/lofi` origin/public mount returns audio bytes while OnAir says live; a 404 or unreachable mount is never shown as live.
- Parallel 401 responses produce one refresh request, and OnAir no longer shares the legacy Wall browser profile.
- Targeted Python, frontend contract, guard, startup-reconcile, public-status, and desktop tests pass before packaging or live cutover.

## High-assurance durability pass (2026-08-08)

- The worker lease is now acquired atomically with an owner/expiry-fenced UPSERT. Each backend process uses a unique PID/UUID owner, malformed or implausibly future-dated leases are recoverable, and concurrent contenders cannot both become scheduler owner.
- Worker-loop diagnostics expose heartbeat age, tick duration, in-progress state, and an explicit 60-second stall signal. The external Windows supervisor escalates a frozen tick to a full backend replacement, uses 1/2/5/15/30/60-second exception backoff, rotates its log at 10 MB with five backups, and identifies both Python backends and the verified owner of reserved port 8100.
- Start, stop, and recover operations are serialized per station. SQLite callers use bounded busy timeouts, audit logging uses a short 250 ms lock budget, and startup duration backfill has per-file and total FFprobe deadlines instead of allowing one damaged/network file to hold startup indefinitely.
- Unread FFmpeg stderr pipes were removed from recording and direct-Icecast paths. Recorder termination escalates from wait to terminate to kill, and decoded sound-effect buffers are capped at five seconds.
- The critical Lo-Fi freeze was reproduced and isolated: after a failed mount probe the app stopped feeding PCM to the Icecast encoder, but the encoder needed PCM to recreate the mount. This circular gate left FFmpeg alive while the broadcast could never recover.
- Icecast PCM now crosses a bounded 64-chunk asynchronous queue. A blocked remote encoder can no longer block the decoder/worker thread; queue saturation is measured and reported, stop/recovery tears down the blocked encoder, and replacement encoders continue receiving PCM even while the remote mount is still being verified. Decode heartbeat and remote listener health are intentionally separate signals.
