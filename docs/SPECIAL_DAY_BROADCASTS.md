# Special-day broadcasts

The **Özel günler** workspace stores independent plans for the selected station. Plans and current playlist position are persisted in two independent additive SQLite tables. Playlist payloads stay out of the ordinary station-settings queries, so large future lists cannot burden normal playout polls. Outputs and credentials are not migrated.

1. Select the target channel and create a named plan.
2. Set an inclusive date range, local start/end clocks and timezone (default Europe/Istanbul). The clocks apply each day in that date range. Equal clocks mean 24 hours; an end clock before the start crosses midnight. Enable annual repetition for dates such as 29 October or 10 November.
3. Choose **Klasör seç**. The default button uses the browser OS folder dialog; **RadioTEDU masaüstünde yerinden seç** uses the existing desktop native Windows dialog and reads audio in place. In a browser, selected files are copied without transcoding into a separate special-event media pool. Alternatively enter an absolute folder path and scan. Select songs, drag their order or use the up/down controls. Folder refresh preserves retained selection/order and adds new files; save after refreshing. A failed/incomplete scan never publishes a partial list.
4. Select ordered or deterministic shuffled playback, playlist repeat and crossfade (0–10 seconds).
5. New plans default to **Çalan şarkı bitince (önerilen)**, also the API default. A programme scheduled for 09:00 starts at the current song's clean EOF, for example 09:02. Decoder draining/finalization is still part of that song. Its accepted audio tail stays in the persistent output FIFO with no initial overlap; subsequent programme songs use the configured crossfade. Completed predecessors use normal completion and ledger callbacks rather than replaying after the programme. Existing explicit `exact` plans remain exact. Select **Saatinde devral (çalan şarkıyı kesebilir)** only when that interruption is intended. At the exclusive end instant the station returns to its normal queue; the delayed start does not extend the end time. An exact takeover requeues interrupted regular automation instead of consuming it. Live show audio retains its existing ownership; scheduled metadata applies at its clock window even while playlist audio waits for EOF.
6. Optionally set one fixed metadata line. A **metadata-only** plan can span the whole day while a separate playlist plan spans a shorter interval. Higher priority wins each independent audio/metadata selection; equal priorities use stable plan IDs. Removing or ending the override restores the latest normal title/artist. The metadata control never calls audio start/stop.
7. Save and verify the returned durable record. Pause/resume and removal require read-back; removal uses a second click. A duplicate creation request with identical content returns the existing revision instead of restarting an active programme.

The pool remains separate from the ordinary live-folder library. Selecting a folder does not publish a plan. Imported bytes remain unchanged; the configured output codecs, bitrates, quality branches, credentials and regular folders are not edited. Missing sources fall back to normal continuity with a 30-second retry, while persisted position permits restart recovery inside the active window. Other stations are unaffected.

API: authenticated station-local CRUD at /api/stations/{station_id}/special-events; folder preview and multipart audio import at /api/special-event-media/*. Admin, DJ and producer roles may operate these routes; viewers may not. Folder/audio import is bounded to 2,000 tracks and 512 MiB per file, and publication validates selected paths. Long file writes run outside the ASGI event loop.

Run focused Python tests and every JavaScript test before any supervisor restart. Verify production with fresh decoded audio, not TCP alone, and retain a verified online SQLite backup plus the previous native service configuration.

Before live deployment, take an integrity-verified online SQLite backup and create the two empty additive tables through `ensure_schema` while the current service remains running. Verify the saved output/folder contract. This avoids first-boot schema-backup work during the controlled reconnect; old versions ignore the new tables. Keep the original native service definition for rollback.
